# Google Calendar / Meet API（`gcp_*_requests_peak_minute`）

[← 一覧](./README.md) ・ クォータ: **1 分あたりのリクエスト数**（全呼び出しが 1 つの共有アカウントから出るので、ユーザーごとの上限が効く）。
超えると Google が 429 / 403 を返し、カレンダー・ミーティング・出席の同期が一時的に失敗する。**課金はされない**。
画面の値は直近 24 時間で最も混んだ 1 分。上限の値は Google の資料で未確認（`limits.ts` の注記）。

## よくある原因

- 一斉同期（全員分を同じ分に取りに行く）・cron の同時起動
- 429 の後にすぐ再試行して、さらに混む
- 差分同期（`syncToken`）を使わず毎回全件を取る

## 使っている所の調べ方

- Dub 側の記録: D1 の `driveshare_google_api_usage`（usage-meter の gcp collector が読むもの）を分単位で見る
- Google 側: GCP コンソール → API とサービス → 対象 API → 指標・割り当て

## 対策

1. 同期の開始時刻をずらす（ジッター）・1 分あたりの呼び出し数に上限を付ける
2. 429 は指数バックオフで待つ
3. `syncToken` で差分だけ取る

## 課金が正しい時

課金プランは無い。上限を上げたい時は **GCP コンソールからクォータの引き上げを申請**する（$0）。
