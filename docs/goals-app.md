## 目的とスコープ

チームごとに 1 か月の目標と KPI を置き、進捗を Dub の各アプリのデータから自動で集計して % で見せる。
報告のために手で数字を集める手間をなくす。

## 進捗の計算

- **KPI の達成率** = 実績 ÷ 目標値。100% を超えても超えたまま表示する（棒は 100% で頭打ち）。
- **チームの進捗** = KPI ごとの達成率を 100 で頭打ちにした平均。1 つの超過で他の未達が隠れないようにするため。
- % は切り捨て（未達を四捨五入で 100% に見せない）。重みは付けない。集計できなかった KPI は平均から除く。
- 「達成」は全 KPI を数えられて、すべて目標に届いた時だけ出す。
- 月は**日本時間の暦月**。カードの棒の縦線は月の経過（今日まで）の目印。

実績は保存せず表示のたびに数える。過去の月も今のデータから数え直すので、後から直した内容はそこにも反映される。
取得に失敗した指標は 0 ではなく「集計できませんでした」と出す（止まった連携を進捗 0% に見せない）。

## 集計する指標

定義の SoT は `@dub/types` の `goal.GOAL_METRICS`。

| 指標 | 範囲 | 数え方 |
|---|---|---|
| タスク完了数 | チーム | 期限がその月のタスクのうち完了した数 |
| タスク完了率 | チーム | 期限がその月のタスクのうち完了した割合 |
| 応募者数 | 全体 | その月に登録された応募者 |
| 面談数 | 全体 | 面談日がその月の応募者 |
| 採用数 | 全体 | その月に採用へ進めた応募者（同じ人は 1 回） |
| 名刺の登録数 | 全体 | その月に登録された名刺 |
| 参加届の提出数 | 全体 | その月に提出された参加届 |
| LP の訪問者数 | 全体 | その月の一意の訪問者（bot を除く） |
| 手入力 | チーム | Dub で数えられない数字を実績欄に入れる |

**タスクは期限で数える**。`task_tasks` に完了日時が無く、`updated_at` は完了後の編集でずれるため。中止・アーカイブ・
チーム未設定のタスク（カレンダーの予定を含む）、子を持つ親タスクは数えない。**期限の無いタスクは数えない**。

チーム別のデータを持たない指標は全体の数字で、画面に「（全体）」と出す。

## データモデルと実装場所

D1 `member` namespace に `member_goals` を 1 つ（1 チーム 1 か月 1 行、`version` で楽観ロック）。KPI は単体で検索しないので
`kpis_json` に持つ。

人事・スポンサーと同じ理由で member-service を拡張した（ゲートウェイ・新しい Worker が不要で $0 を崩さない）。

- `src/goal-repo.ts`: 永続化と実績の取り口。人事・スポンサー・参加届は同じ namespace なので直接数える。
- `src/goal-service.ts`: 検証と集計。
- 他サービスの namespace は読まず、件数だけ返す内部 API を Service Binding で呼ぶ:
  task-service `GET /internal/goal-metrics`、lp-analytics `GET /lp/internal/goal-metrics`。
  閲覧者が task:read を持たなくても件数は見える（行の中身は返さない）。

API: `GET /members/goals?month=YYYY-MM`、`PUT /members/goals/:teamId/:month`、`DELETE /members/goals/:teamId/:month`。

## 権限（ロール管理）

| キー | 意味 | 既定 |
|---|---|---|
| `app:goals:view` / `app:goals:edit` | 無効/閲覧/編集 | admin のみ |
| `goals:read` | 目標と進捗の閲覧（閲覧を付けると自動で入る） | admin のみ |

編集できる人は全チームの目標を編集できる（チームごとの制限は無い）。

## リリース手順と migration

1. demo で確認 → staging で実 backend（D1・Service Binding の往復）を確認 → 本番 → ロールに権限を付与 →
   メンバー公開（`PUBLISHED_APPS` に `goals` を足す 1 行）。
2. **本番デプロイ前に D1 migration を適用する**（前方のみ・additive）:
   - `infra/d1/migrations/member/0023_goals.sql`
   - `infra/d1/migrations/identity/0031_goals_app_perms.sql`
3. member-service の Service Binding が増えるので、task-service / lp-analytics の内部 API が先に出ている必要がある。
   順序が逆でも該当 KPI が「集計できませんでした」になるだけで、ほかは動く。
